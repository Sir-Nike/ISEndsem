Lab 5 Q3: MD5, SHA-1 and SHA-256 experiment

What the manual asks

Generate 50–100 random strings; measure MD5/SHA-1/SHA-256 computation time and detect collisions within the dataset.

Start here: the idea in plain English

Generate unique random strings so a repeated input is not mislabeled as a collision. For each algorithm, build a mapping from digest to original string and look for a different string with the same digest. Time repeated full-dataset hashing passes. A tiny random dataset will normally have no collisions; that does not establish cryptographic collision resistance.

Step-by-step solution

1. Start the program and select Run. Read the displayed default inputs before changing them.
2. Follow the input prompts. Text is encoded to bytes when required; numeric inputs are checked before cryptographic operations.
3. Read the exercise() function below: it connects the functions in the order needed for this question.
4. Compare the printed output with the expected result, and repeat using a different input.

def exercise():
    """Input: dataset count in 50..100 and repeat count. Compare the three digest algorithms.
    Output: sample digests, mean dataset hashing time and observed distinct-input collisions.
    """
    values = generate_dataset(ask_int("Number of strings", 75, 50, 100))
    repeats = ask_int("Timing repetitions", 100, 1, 10000)
    for algorithm in ("md5", "sha1", "sha256"):
        start = time.perf_counter()
        for _ in range(repeats):
            for text in values:
                hashlib.new(algorithm, text.encode()).digest()
        elapsed = (time.perf_counter() - start) / repeats
        collisions = detect_collisions(values, algorithm)
        print(algorithm, "sample digest:", hashlib.new(algorithm, values[0].encode()).hexdigest())
        print("Mean dataset time s:", elapsed, "Observed collisions:", collisions)
    print(
        "No observed collisions in a small random sample is not evidence of cryptographic collision resistance."
    )


Follow the calls in exercise() from top to bottom. It obtains the inputs, calls the small functions that do the work, and prints intermediate values and the final result. Bytes are shown as hexadecimal when ordinary text would be unreadable. A successful round trip prints a recovered message equal to the input; verification examples also show a changed message being rejected where applicable.

Every function explained

ask_text(label, default)

Input: a prompt and default string. Read text, or use the default when Enter is pressed.
Output: a string. Use ask_text('Message', 'hello') to let the user choose a message.

ask_int(label, default, minimum, maximum)

Input: prompt, default integer, optional inclusive limits. Read and validate a number.
Output: an integer; raise ValueError on bad input. Use for keys, counts, or amounts.

generate_dataset(count, length)

Input: number of unique strings and characters per string. Generate random ASCII text.
Output: sorted list of unique strings. Duplicate input strings are deliberately removed.

detect_collisions(strings, algorithm)

Input: strings and hashlib algorithm name. Map digests to their first distinct input.
Output: list of (first input, second input, digest) collisions; repeats are not collisions.

exercise()

Input: dataset count in 50..100 and repeat count. Compare the three digest algorithms.
Output: sample digests, mean dataset hashing time and observed distinct-input collisions.

main()

Input: terminal choices. Run the exercise safely.
Output: printed results. Use python solution.py and choose a menu option.

What to change during an exam

Change values through the prompts first. For a different scenario, replace the example messages or record fields in exercise(), and keep the cryptographic functions. Match the requested algorithm, key size, mode, and hash exactly. Store IVs/nonces alongside ciphertext when needed. Keep private keys private. Hashing cannot be decrypted; encryption can. A hash by itself does not prove who sent a message.

Notes and limitations

MD5 and SHA-1 have known cryptographic collision weaknesses; random sampling of 50–100 strings does not reproduce those attacks. SHA-256 is the appropriate secure-hash example among these three. The experiment measures local execution time and observed sample collisions only.
